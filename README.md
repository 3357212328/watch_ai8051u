# AI8051U 创新项目

基于 STC AI8051U 单片机的综合外设驱动库项目，使用 **AI8051U 专属库函数**（位于 `D:\embeded electronic\stc\AI8051U专用库函数\`）进行开发。

## 芯片简介

AI8051U 是 STC 推出的增强型 8051 内核单片机，集成 **MDU32**（32位硬件乘除法单元）和 **TFPU**（三角函数浮点运算单元），支持硬件数学加速，主频高达 42MHz，适用于工业控制、电机驱动、传感器采集等场景。

## 开发环境

- **IDE**: Keil C251
- **芯片型号**: AI8051U-32bit（251指令集）
- **编程语言**: C

### 时间精度

RTC 只能吃 32.768 kHz 时钟源，本板没有 32.768K 晶振（也没有焊盘），因此固定使用芯片内部 IRC32K（RC 振荡器）。手册「附录G 电气特性」给出内部 IRC 温漂：**-20~65℃ 为 -0.88%~+1.05%**，折算约 **每小时 30~40 秒**。所以「放几小时后差近一分钟」是时钟源本身的频率误差，不是固件丢秒或读数错位；芯片里也没有任何 32K 频率修调位（`IRC32KCR` 只有使能位和稳定标志），单靠改固件不可能彻底消除。

固件提供的三条路径，按现场条件选一条：

| 场景 | 行为 |
|------|------|
| USB 插电脑（主机在线） | 每 20 ms 读 SIE 的 11 位 SOF 帧计数（1 帧 = 1 ms，精度由主机晶振决定，通常 ±50 ppm）。以「两个 RTC 秒边界之间主机走了多少毫秒」为单位测速率：理想是 1000 ms，差值累加，累计满 1 秒就整秒拨慢/拨快一次（秒值为 0 或 59 时顺延到下一秒，不碰日历）。插电脑时走时自动跟住电脑时钟，误差压到 1 秒内 |
| USB 插充电宝 / 电源适配器 | `DeviceState == 0`，读帧计数的代码直接返回，不碰 USB 寄存器；RTC 自由走时，仍按上面的温漂漂移 |
| 想减小漂移（无需任何硬件） | 把 `watch_time.c` 顶部的 `WATCH_TRIM_SPD` 改成实测值：**每天快多少秒就填多少**，走慢填负数。固件每 `86400 ÷ 绝对值` 秒把 RTC 整秒拨一次，补偿这一个方向的固定漂移，通常能把误差压到原来的 1/3 左右 |

**怎么定 `WATCH_TRIM_SPD`**：先对一次时，让它跑几小时（越久越准，建议 ≥ 6 小时，最好 1 天），再和手机/电脑对时：

```
误差秒数 = 表上的时间 - 基准时间      （表快了为正）
运行秒数 = 对时后经过的时间
WATCH_TRIM_SPD = 误差秒数 × 86400 ÷ 运行秒数
```

例：跑了 6 小时慢了 90 秒 → `90 × 86400 ÷ 21600 = 360`，填 `-360`。该值要求绝对值 ≥ 2。

为什么是编译期常量而不是菜单项：早期版本 code+const 占满 64 KB（余 < 400 B），没有 EEPROM 扇区可放参数；2026-11 精简后固件约 53.1 KB（余 ~12.4 KB），已能划出 1~2 KB EEPROM，但校准值仍保留为编译期宏：本板 RTC 无后备电池，开机时间每次归零，漂移只能在连续运行中实测标定，填宏比在菜单里存一个数更直接。RC 漂移随温度变化，一个固定值只能补偿平均值，不能做到完全准确。

另外 `WATCH_USE_X32K`（默认 0）保留给将来焊了 32.768 kHz 晶振的板子：置 1 后上电最多等约 1 秒等起振，成功后精度到 ppm 级（每天 < 1 秒），起振失败自动回退 IRC32K。

纠偏会重写 RTC 秒寄存器（`WatchTime_Set`），所以偶尔能看到秒数「重复一秒」或「跳过一秒」，属正常。

### RTC 对时（STC-ISP / AI-ISP「设置RTC」）

固件在 USB-CDC 数据流上内置了官方「设置RTC」命令帧的增量解析器（`usb_ctrl.c`，主循环上下文，帧可跨 USB 包重组）：

1. STC-ISP / AI-ISP 的 USB-CDC 串口页，**「命令头」必须留空**（固件按无头二进制流同步，自定义头部不解析）。
2. 点击「设置RTC」：工具发出 **11 字节二进制帧**（纯 HEX 非 BCD）：
   `世纪(0x14 或 0x20) | 年(0~99=20YY) | 月(1~12) | 日(1~31) | 星期(0=周日..6=周六) | 时(0~23) | 分(0~59) | 秒(0~59) | 次秒(0~127, 1/128s) | 毫秒(2 字节大端, 0~999)`
3. 固件逐字节范围校验 + 毫秒≤999 + **星期与日期做 Zeller 交叉校验**，任一不符整帧丢弃并复位；通过即在主循环写入片上 RTC（`WatchTime_Set` 全字段钳位 + SETRTC 重载），对时生效后表盘时间立即变化，同时串口回发确认 `Time set: 20YY-MM-DD HH:MM:SS`。
4. 帧字节不会进入按键解码（次秒/毫秒字节如 0x65='e' 不会误触虚拟键）；正常击键 ASCII 与同步字节不冲突，日常输入不受影响。
5. 偶发丢帧（工具提示发送失败或时间未动）时**再点一次「设置RTC」**即可；毫秒字段仅作校验，RTC 重载将子秒清零（既有 `INISSEC=0` 语义），对时精度为整秒级。
6. 注意：对时期间不要在工具的串口助手页同时打开同一 COM 口（会占用失败）。

### 关键实现约束

- C89（Keil C251），所有菜单数据为定位初始化器，`MenuWindow`/`MenuPage`/`MenuItem` 字段顺序详见 `oled_ui_menudata.c` 头部注释。
- `edata` 仅保留速度敏感变量（ISR 上下文的 `WatchTickFire`、框架类型钉死的 `Watch_Stage*` 六个暂存 int16），其余状态量在 `xdata`（超时溢出策略：优先迁 xdata）。
- 框架契约：`OLED_UI_MainLoop()` 每帧（菜单模式由 `Watch_Render` 菜单分支驱动）、`OLED_UI_InterruptHandler()` 每 20ms tick（`Watch_Tick` 驱动）；表盘/秒表模式自行消耗全部 `USBCtrl_Take*`/`Encoder_Get`，防止虚拟脉冲泄漏进菜单。
- 构建：`build.bat` 或 `UV4.exe -r ai8051u_templete.uvproj -j0 -o build.log`；当前 0 Error/0 Warning，code 49,295 + const 3,769 = **53,065 B / 64 KB**（余约 12.4K 字节），data 8.4，edata+hdata 1937/2048，xdata 4510/32768。烧录前请确认 STC-ISP 的「EEPROM 大小设置」为 0K（或 ≤8K）；程序区 64 KB 时固件只占 53.1 KB，即使划 8 KB EEPROM 也能装下。
- 刷新策略：`OLED_Update()` 逐页比对显存镜像，只推送内容变化的页（颜色模式真变化时强制整屏推送，保证反色闪屏不丢）；编码器在 I2C 忙等中采样，快速旋转不丢步。
